这份代码整体上已经不是单纯的 PatchTST 或 iTransformer，而是一个面向 M5 零售销量预测的多变量时序编码 + 跨商品注意力 + 未来协变量条件化预测的混合架构。

它有两条独立训练的预测分支：

- Sales-only：只利用历史销量，作为基线模型。
- Multi-feature：利用历史销量、历史价格与日历特征，并在预测时引入已知的未来日历特征和经过因果处理的价格特征。

两条分支还可以进行 50% : 50% 的预测集成。

从架构设计来看，当前 `ARCH="v2"` 的核心是：PatchTST 提取每个商品的时间模式，iTransformer 风格的注意力建模商品之间的关联，再通过历史注意力和预测区间注意力生成未来 28 天的销量。

下面按照数据流、网络结构、张量维度和训练流程拆解。

# 一、模型整体架构

### 输入层

历史 112 天 · N 个商品 · 每日销量与协变量

Sales-only

历史销量 [B,112,N]

Multi-feature

历史销量 + F 个历史特征

### ① PatchTST 时间编码器

112 天切分为 13 个重叠 Patch，每个 Patch 投影至 64 维

共享时间编码器 · 2 层 Transformer · 8 头注意力

### ② 跨商品注意力（v2）

每一个时间 Patch 内，N 个商品互相交换信息

MultiheadAttention + FFN + 残差连接

### ③ 未来条件化查询

预测日历/价格特征 → Future Covariate Projection

与每个预测日的 Query 融合

### ④ 历史注意力 + 预测区间注意力

每个未来日期检索历史 Patch，再让 28 个预测日期相互交互

### ⑤ Forecast Head

每个商品、每天输出一个标准化对数销量预测

输出 [B,28,N] → 反标准化 → 还原销量

这里的 `B` 是批次大小，默认 32；`N` 是商品数量，默认 50；`F` 是协变量数量，取决于日历事件类别等实际数据。

注意：上图展示的是 `v2` 主干。Sales-only 不包含未来协变量投影与融合，但仍使用相同的 PatchTST、跨商品注意力、历史注意力、预测区间注意力和预测头。

# 二、第一部分：输入数据到底是什么？

## 1. 预测对象

默认配置：

| 参数                  | 默认值 | 含义                  |
| ------------------- | --- | ------------------- |
| `N_ITEMS`           | 50  | 随机选取 50 个 `item_id` |
| `HISTORY`           | 112 | 历史 112 天            |
| `HORIZON`           | 28  | 一次预测未来 28 天         |
| `BATCH_SIZE`        | 32  | 每批 32 个时间窗口         |
| `PATCH_LEN`         | 16  | 每个 Patch 包含 16 天    |
| `PATCH_STRIDE`      | 8   | Patch 每次向前移动 8 天    |
| `D_MODEL`           | 64  | 隐藏表示维度              |
| `N_HEADS`           | 8   | 多头注意力头数             |
| `N_TEMPORAL_LAYERS` | 2   | 时间 Transformer 层数   |
| `DROPOUT`           | 0.1 | Dropout 比率          |

这里有一个值得注意的地方：虽然默认选择 50 个 `item_id`，但每个商品会汇总所有选中门店的销量。因此，模型预测的是跨门店汇总后的商品日销量，而不是单个门店的销量。

例如，商品 A 在 CA、TX、WI 各门店的销量会先加总，再作为商品 A 的每日标签。

## 2. Multi-feature 分支的特征

代码将输入分成两类。

历史输入：

- 历史销量：112 天。
- 历史日历：星期、月份、年周周期、年份、零售周索引。
- 历史促销相关信息：SNAP 标记、对应商品门店的 SNAP 覆盖比例。
- 历史价格：均价、价格标准差、价格覆盖率、价格陈旧程度。
- 日历事件：节日名称、事件类型等独热编码。

未来已知输入：

- 未来 28 天的星期、月份、周周期。
- 已知的节日及事件特征。
- 已知的 SNAP 日历信息。
- 截至预测时点可用的价格信息，以及价格覆盖率和陈旧程度。

其中，价格并不是简单地使用完整 CSV 中未来目标周的实际价格。函数 `future_covariates_as_of()` 会在每个预测起点重新构造未来价格特征，只使用该起点之前可用的价格记录。

这对避免价格信息泄漏非常重要。

## 3. 数据预处理流程

原始 M5 数据

sales_train_validation、calendar、sell_prices

商品级日销量聚合

按 item_id 汇总门店销量，形成 [天数, 商品数] 矩阵

日历编码 + 价格因果填充

周期编码、事件独热、历史价格前向填充、价格年龄记录

训练集拟合缩放器

销量 log1p 后按商品标准化；连续协变量只用训练日期拟合标准化参数

滑动窗口构造

输入历史 112 天，标签未来 28 天

销量标签采用：

\\[ z\_{t,i}=\frac{\log(1+y\_{t,i})-\mu_i}{\sigma_i} \\]

这里的 \\(\mu_i,\sigma_i\\) 是第 \\(i\\) 个商品在训练时间段内的对数销量均值和标准差。

这样做有两个作用：降低销量分布的偏态和极端值影响，同时避免高销量商品在训练损失中天然占据过大权重。

不过，这也意味着训练目标并不是原始销量尺度上的 MAE 或 WAPE 最优化，而是标准化对数销量空间中的损失最小化。

# 三、第二部分：PatchTST 时间编码器

这是整个模型的第一个核心模块。

## 1. 为什么把 112 天切成 Patch？

默认历史长度为 112 天，Patch 长度 16，步长 8：

\\[ P=1+\left\lfloor\frac{112-16}{8}\right\rfloor=13 \\]

也就是说，每个商品的历史序列会被切成 13 个有重叠的时间片段。

一个商品的历史销量序列：112 天

Patch 1

连续 16 天

Patch 2

连续 16 天

Patch 3

连续 16 天

Patch 4

连续 16 天

每个 Patch 向前移动 8 天，相邻 Patch 重叠 8 天。上图只展示前几个 Patch 的切分方式。

Patch 的优势在于：模型不必直接把 112 个单日时间步都当作 Transformer token，而是先学习局部时间片段的整体模式。

例如，一个 Patch 可以包含：

- 连续几天销量上升；
- 周末销量明显提高；
- 某次促销前后的销量变化；
- 短期波动和局部峰值。

但要注意：Patch 本身并不直接等于一个星期或一个业务周期。这里长度为 16 天，步长为 8 天，是重叠窗口设计，而不是按自然周切分。

## 2. Patch 投影

对于 Sales-only，每个 Patch 的输入是 16 个销量值：

\\[ \mathbf{x}\_{i,p}\in\mathbb{R}^{16} \\]

对于 Multi-feature，每个时间点包含销量和 \\(F\\) 个协变量，因此：

\\[ \mathbf{x}\_{i,p}\in\mathbb{R}^{16(1+F)} \\]

对应代码：

```
self.patch_proj = nn.Linear(    patch_len * self.n_input_channels,    d_model)
```

将每个 Patch 映射为 64 维向量：

\\[ \mathbf{e}\_{i,p} = W_p\mathbf{x}\_{i,p}+b_p \\]

随后加入可学习的时间位置编码 `temporal_pos`，让模型能够区分历史窗口中不同位置的 Patch。

## 3. 时间 Transformer

```
self.temporal_encoder = nn.TransformerEncoder(    enc_layer,    num_layers=temporal_layers)
```

默认两层，每层包含：

- 8 头自注意力；
- 前馈网络，隐藏维度 \\(4D=256\\)；
- GELU 激活；
- 残差连接和 LayerNorm；
- Dropout。

其输入形状为：

\\[ [B\times N,\ 13,\ 64] \\]

其中每个商品单独进入时间编码器。不同商品使用同一套时间编码器参数，但它们的销量和特征输入不同，因此得到不同的时间表示。

输出重新整理为：

\\[ [B,N,13,64] \\]

这一点符合 PatchTST 的核心思路：先学习每个商品自己的时间结构，再进入跨商品交互模块。

需要区分的是，代码并没有在 PatchTST 阶段直接让商品 A 和商品 B 进行注意力交互；商品间交互发生在下一阶段。

# 四、第三部分：iTransformer 风格的跨商品注意力

这是 `v2` 相较于传统 PatchTST 时间编码器的关键扩展之一。

## 1. 它解决什么问题？

PatchTST 主要关注单个商品自己的历史模式，但零售商品之间往往存在关系：

- 替代关系：一种商品销量上升时，另一种可能下降。
- 互补关系：关联商品可能同时增加销量。
- 共同需求：多个商品同时受到节日、天气或促销环境影响。
- 同步变化：不同商品存在共同的需求趋势或周期性。

因此，模型需要让一个商品的表示能够利用其他商品的信息。

## 2. 当前代码如何实现？

先看核心代码：

```
# [B,N,P,D] -> [B,P,N,D] -> [B*P,N,D]pt = patch_tokens.permute(    0, 2, 1, 3).reshape(b * p, n, -1)att, _ = self.item_attention(    self.item_norm1(pt),    pt,    pt,    need_weights=False)pt = pt + attpt = pt + self.item_ffn(self.item_norm2(pt))
```

这里的注意力不是对每个商品的全部历史进行平均后再交互，而是在每一个历史 Patch 位置上，让所有商品互相注意。

例如，假设有 50 个商品：

第 1 个历史 Patch

商品 A

商品 B

商品 C

商品 D

…

商品维度的 Multi-Head Attention

每个商品的 Query 都可以读取其他商品的 Key / Value

A′

融合后

B′

融合后

C′

融合后

D′

融合后

…

融合后

每个 Patch 都独立执行一次相同的跨商品注意力计算，时间轴上的 13 个位置不会在这一阶段被合并。

对第 \\(p\\) 个 Patch：

\\[ X_p\in\mathbb{R}^{N\times D} \\]

注意力的基本形式为：

\\[ \operatorname{Attention}(Q,K,V) = \operatorname{softmax} \left( \frac{QK^\top}{\sqrt{d_k}} \right)V \\]

输出形状仍然是：

\\[ [B\times P,N,D] \\]

最后恢复为：

\\[ [B,N,P,D] \\]

### 为什么说它是 iTransformer 风格，而不是标准 iTransformer？

原始 iTransformer 的核心是把每个变量的历史序列编码成一个变量 token，再在变量 token 之间执行注意力。

当前代码则先通过 PatchTST 得到每个商品的多个 Patch token，然后在每个 Patch 的同一时间位置上进行商品注意力。

两者都把变量或商品维度作为注意力交互的对象，但当前模型保留了 Patch 时间轴，因此并不是原始 iTransformer 的直接复现。

此外，当前代码中的商品是被随机抽取的 50 个商品，模型学习的是这个固定商品集合内部的关系，并不意味着它能自动推广到任意新商品。

# 五、第四部分：未来条件化查询与历史注意力

这一部分是当前架构真正将“未来已知特征”与“历史模式”结合起来的地方。

## 1. 为什么需要 Query？

经过 PatchTST 和跨商品注意力后，每个商品有 13 个历史表示：

\\[ H_i\in\mathbb{R}^{13\times64} \\]

但是我们需要预测未来 28 天，而不是输出一个历史总结。因此，模型需要为每个未来日期建立一个查询向量，去历史表示中寻找与该预测日期有关的信息。

代码中使用可学习的 `horizon_embedding`：

```
query = self.horizon_embedding[    :, :self.horizon].expand(b, self.horizon, n, -1).contiguous()
```

它为每个预测步提供一个独立的初始表示。比如第 1 天和第 28 天的 Query 不一样。

如果启用了商品嵌入，还会加上对应商品的身份向量。

## 2. 未来协变量如何进入 Query？

Multi-feature 分支先对未来特征做投影：

```
future_emb = self.future_cov_proj(x_cov_future)query = self._condition_query(query, future_emb)
```

未来协变量投影网络是：

```
nn.Sequential(    nn.Linear(n_covariates, d_model),    nn.GELU(),    nn.Linear(d_model, d_model),)
```

因此，原始的 \\(F\\) 维未来特征被映射到 64 维空间。

默认 `COV_FUSION="add"`，融合公式为：

\\[ Q\_{h,i}^{(0)} = E_h+E_i+W_f(C\_{h,i}) \\]

其中：

- \\(E_h\\)：预测步的可学习嵌入；
- \\(E_i\\)：可选的商品身份嵌入；
- \\(C\_{h,i}\\)：第 \\(h\\) 个未来日期、商品 \\(i\\) 的协变量；
- \\(W_f\\)：未来特征投影网络。

当 `ITEM_EMBED=false` 时，公式中不包含 \\(E_i\\)。

这里最重要的设计是：未来日历和价格信息进入历史注意力的 Query，而不是等到预测输出前才简单拼接一次。

## 3. Query 如何检索历史？

```
history_attended, _ = self.history_attention(    self.history_query_norm(query_bn),    history_bn,    history_bn,    need_weights=False)query_bn = self.history_attn_norm(    query_bn + history_attended)
```

在这一层：

- Query：未来 28 天的预测表示；
- Key：历史 13 个 Patch 表示；
- Value：历史 13 个 Patch 表示。

数学上，对商品 \\(i\\) 的第 \\(h\\) 个预测日：

\\[ Z\_{h,i} = \operatorname{Attention} \left( Q\_{h,i},H_i,H_i \right) \\]

其中 \\(Z\_{h,i}\\) 是从历史 Patch 中读取的信息。

因为 Query 已经融合了未来特征，模型原则上可以学习不同的条件化检索方式。例如，在节假日预测日，模型可能更加关注历史节假日附近的 Patch；在普通工作日，则可能更加关注常规周内模式。

但要强调：这是网络有能力学习的机制，不是代码已经保证它一定学会了节假日匹配。需要通过消融实验和验证集结果判断其实际作用。

## 4. `add`、`gate`、`proj` 有什么不同？

| 模式     | 融合方式                          | 特点              |
| ------ | ----------------------------- | --------------- |
| `add`  | \\(Q+C\\)                     | 简单直接，默认设置       |
| `gate` | \\(Q+\sigma(W[Q,C])\odot C\\) | 学习每个维度应接收多少未来特征 |
| `proj` | \\(Q+\operatorname{MLP}(C)\\) | 对未来特征进行额外非线性变换  |

三种方式都发生在历史注意力之前。

其中 `gate` 更灵活，可以根据当前 Query 和未来特征共同决定融合强度；但参数更多，不代表一定更准确。建议通过相同数据切分和相同随机种子的消融实验比较。

# 六、第五部分：预测区间注意力与输出头

经过历史注意力后，每个商品已经有 28 个未来预测表示：

\\[ Q_i\in\mathbb{R}^{28\times64} \\]

`v2` 接下来增加了一层预测区间自注意力。

```
h_att, _ = self.horizon_attention(    self.horizon_query_norm(query_bn),    query_bn,    query_bn,    need_weights=False)query_bn = self.horizon_norm(query_bn + h_att)
```

## 1. 这层注意力有什么意义？

历史注意力负责让每个预测日检索过去，而预测区间注意力让不同的预测日期之间交流信息。

例如：

- 第 6 天可以参考第 7 天的预测表示；
- 周末的预测表示可以利用相邻工作日的表示；
- 28 天内的需求走势可以通过不同预测步的交互得到协调。

这是一种直接多步预测（Direct Multi-horizon Forecasting）：28 天同时预测，而不是先预测第 1 天，再把预测结果作为第 2 天的输入，依此递推。

因此，它不会因为自回归递推而逐步累积预测误差。

不过，当前 `horizon_attention` 没有使用因果 mask。这对于当前的直接多步预测设计是允许的：因为 28 个 Query 都只含已知的未来协变量、可学习的预测步嵌入以及历史信息，没有把真实的未来销量放入 Query。

它学习的是不同预测步之间的表示关系，而不是读取未来真实标签。

## 2. Forecast Head

最后，每个未来日期、每个商品的 64 维表示进入同一个预测头：

```
self.forecast_head = nn.Sequential(    nn.LayerNorm(d_model),    nn.Linear(d_model, d_model),    nn.GELU(),    nn.Dropout(dropout),    nn.Linear(d_model, 1),)
```

计算为：

\\[ \hat z\_{h,i}=f\_\theta(Q\_{h,i}) \\]

输出形状是：

\\[ \boxed{\hat Z\in\mathbb{R}^{B\times28\times N}} \\]

模型先预测标准化对数销量，再通过反标准化还原：

\\[ \hat y\_{h,i} = \max\left( \exp(\hat z\_{h,i}\sigma_i+\mu_i)-1,\ 0 \right) \\]

这个输出头对所有商品共享参数。商品之间的区别主要由输入历史、跨商品交互以及可选的商品嵌入来表达。

# 七、v1 和 v2 的真正区别

你保留了两套架构，可以用 `M5_ARCH=v1` 或 `M5_ARCH=v2` 切换。

### v1：原始版本

对照组

PatchTST 输出 [B,N,13,64]

13 个 Patch 取均值 → [B,N,64]

跨商品注意力

28 天 Query → 历史 Patch 注意力 → Forecast Head

主要缺陷：跨商品注意力前先平均掉 13 个 Patch 的时间结构。历史注意力仍然保留原始 Patch 表示，但跨商品交换的信息已经被压缩。

### v2：当前默认版本

默认

PatchTST 输出 [B,N,13,64]

每个 Patch 独立进行跨商品注意力

未来协变量条件化 Query → 历史注意力

28 天预测区间自注意力 → Forecast Head

优势：跨商品交互保留时间位置；预测日期可以读取不同的未来条件；28 个预测步还能交换信息。

v2 的改进不是简单地多加一层 Transformer，而是改变了信息流：

1. v1 先压缩时间轴，再交换商品信息。
2. v2 在每个 Patch 位置上交换商品信息，保留时间结构。
3. v2 将未来协变量融合进历史检索 Query。
4. v2 额外让 28 个预测步相互交互。

因此，v2 的表达能力更强，但也更复杂。它是否优于 v1，需要看相同数据、相同评估协议下的验证结果，而不能只依据架构判断。

# 八、训练方式与模型对比机制

## 1. 两个模型独立训练

代码不是把两个分支放在一个网络中联合训练，而是依次训练两个独立模型：

| 配置       | Sales-only | Multi-feature |
| -------- | ---------- | ------------- |
| 历史销量     | 有          | 有             |
| 历史协变量    | 无          | 有             |
| 未来协变量    | 无          | 有             |
| PatchTST | 有          | 有             |
| 跨商品注意力   | 有          | 有             |
| 历史注意力    | 有          | 有             |
| 预测区间注意力  | 有          | 有             |
| 独立训练     | 是          | 是             |

两次训练之前都会重置随机种子，并使用相同的训练窗口打乱序列。这让对比更公平一些，但不意味着两个模型拥有完全相同的参数初始化：Multi-feature 的输入维度更大，因此它的 `patch_proj` 形状不同。

## 2. 默认训练参数

| 参数                      | 默认设置      |
| ----------------------- | --------- |
| 优化器                     | AdamW     |
| 学习率                     | 0.003     |
| 权重衰减                    | 0.00001   |
| 损失函数                    | HuberLoss |
| 梯度裁剪                    | 1.0       |
| 最大 Epoch                | 50        |
| Early stopping patience | 8         |
| 学习率调度                   | 默认关闭      |
| 最优模型选择                  | 验证损失最低    |

这里有一个重要细节：虽然损失函数可选 MSE、Huber 或 MAE，但默认的 Huber 损失是在标准化对数销量空间中计算，而不是原始销量空间。

如果业务最终关注的是 WAPE 或原始销量 MAE，建议同时监控这些原始尺度指标，并明确区分训练损失与业务评估指标。

## 3. 数据切分

默认 `TRAIN_RATIO=0.70`、`VAL_RATIO=0.15`，剩余 15% 作为测试区间。

- 训练窗口：每一天都可以成为预测起点，只要目标 28 天全部位于训练区间。
- 验证窗口：每隔 7 天评估一次，并补充最后一个完整的验证窗口。
- 测试窗口：每隔 7 天评估一次，并补充最后一个完整的测试窗口。
- 非重叠测试：每隔 28 天评估一次。

需要注意，滚动测试窗口会重复计算一些目标日期。`metrics.csv` 中的 `rolling_overlapping` 和 `non_overlapping` 是两种不同的评估口径，不能混为一谈。

另外，测试集的历史输入可以包含已经发生的验证期销量。这是滚动预测中正常的做法，但前提是每个预测起点只使用当时已知的历史数据。

# 九、目前模型最值得检查的几个问题

从整体设计看，数据流是连贯的，v2 也确实保留了历史 Patch 的时间结构。不过，如果目的是做严谨的时序预测实验，我会优先检查以下问题。

1\. `future_covariates_as_of()` 中的价格处理需要验证

当前通过 `price_coverage > 0` 找到起点之前最近一次有价格覆盖的日期，然后将价格前向延续到未来 28 天。这能避免直接使用目标周的实际价格，但价格可用性本身不一定等于业务中的价格发布时间。

特别是 M5 的价格数据按周提供：如果实际预测时点无法提前获得下一周价格，就应该使用上一个已知周价格。当前实现基本遵循这一原则，但需要确认 `wm_yr_wk`、周切换日期以及真实业务预测时点是否一致。

2\. 当前 50% : 50% 集成权重没有经过验证集优化

```
ens_sales = 0.5 * (    sales_only_sales + multi_feature_sales)
```

两个模型的误差可能高度相关，也可能某个模型明显更差。固定平均不一定提高 WAPE。

更严谨的做法是在验证集上寻找融合权重：

\\[ \hat y=\alpha\hat y\_{\text{sales}} +(1-\alpha)\hat y\_{\text{multi}} \\]

例如测试 \\(\alpha=0,0.1,\ldots,1\\)，选定验证集表现最好的权重，然后冻结它，最后只在测试集评估一次。不能根据测试集结果挑选融合权重。

3\. 训练目标与业务指标存在差异

训练时，每个商品的标准化对数销量误差权重接近；评估 WAPE 时，销量较大的商品和日期会对总误差贡献更多。

因此，HuberLoss 更低不保证 WAPE 更低。可以保留 Huber 作为稳定训练的默认方案，再通过验证集对比 MSE、MAE、Huber，并检查原始尺度的 MAE、RMSE、WAPE。

4\. 跨商品注意力的商品集合较小，而且是固定抽样

当前 `N_ITEMS=50`，默认随机选择 50 个商品，模型只能在这个固定集合中建立跨商品关系。

这适合做小规模架构验证，但如果希望推广到完整 M5 商品集合，必须进一步考虑计算成本、商品身份、批量推理，以及新商品的泛化问题。还要确认不同商品的注意力确实学到了有效关系，而不是仅仅增加了模型容量。

5\. 当前验证集只有一个时间区间

当前按时间顺序切分，避免了随机打乱时间造成的主要泄漏风险。但一次验证区间的最优模型不一定能代表其他季节和促销周期。

更可靠的研究方案是增加多个滚动起点，比较不同月份、节假日、普通周的表现；同时保留最终独立测试集，不参与模型选择。

## 十、另外两个值得改进的实现细节

第一，价格缺失值与标准化的处理需要仔细核对。

当前先进行价格前向填充，再标准化连续协变量；未来价格年龄则通过原始年龄的对数值和训练集拟合的缩放参数重新标准化。这个处理总体上是一致的。

但 `PRICE_MASK=true` 时，如果最近一次价格覆盖率低于 0.5，未来价格值会被置零。这里的零代表标准化空间中的零，而不一定对应原始价格为零，因此需要结合覆盖率和价格年龄特征一起解释。

第二，`item_embed` 默认关闭。

`ITEM_EMBED=false` 时，模型没有专门的商品身份嵌入。它主要通过每个商品的历史销量、协变量以及跨商品注意力学习差异。

如果商品存在长期稳定的需求水平、价格敏感度或季节性差异，商品身份嵌入可能有帮助；但它也可能让模型过度依赖训练时固定的商品集合，应该作为独立消融项验证。

# 十一、我对当前架构的总体判断

## 当前模型定位

架构评价，不代表已经通过实验验证的准确率排名。

设计合理的部分

PatchTST 保留局部时间模式；v2 跨商品注意力保留 Patch 维度；未来协变量在历史检索之前进入 Query；训练和预测都采用固定长度的直接多步输出。

需要实验验证的部分

跨商品注意力是否有效、未来特征是否改善预测、预测区间注意力是否优于独立预测步、商品嵌入是否有帮助，以及 50% : 50% 集成是否真正降低误差。

最重要的下一步

先建立简单基线和严格的消融实验，再决定是否增加模型复杂度。不能只比较 v1 与 v2，也应该比较季节性朴素预测、历史同星期销量基线，以及不含跨商品注意力的 PatchTST。

如果接下来要研究这套架构是否适合量化因子预测，可以沿用相同的思想，但需要改变任务设计：将商品维度替换为股票或因子维度，将已知未来日历特征替换为预测时点真实可知的协变量，并对标签构造、横截面标准化、交易时点和滚动回测做严格控制。

最关键的结论是：当前 v2 已经形成了完整的多步预测架构，但复杂度提升只是提供了更强的建模能力，并不等于预测准确率必然提高。 真正决定它是否值得保留的，是在无泄漏的滚动验证中，跨商品注意力、未来条件化查询和预测区间注意力分别带来了多少可重复的增益。
